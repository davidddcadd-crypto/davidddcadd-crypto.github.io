  1. 01 — Request

    Every request arrives the same way

    An agent receives a steady mix of requests: simple lookups, ambiguous asks, risky actions. When a request arrives, nothing about it has been decided.

  2. 02 — Fast first pass

    Laya takes a quick first look

    A fast, local layer gives each request a first classification. That tag is provisional: a suggestion about the route, not permission to act.

  3. 03 — Supervision

    Supervision is not optional

    Luna, the supervisor, spans the whole path. Every request passes through it, and there is no route around it.

  4. 04 — Policy

    Policy decides, not the fast model

    A deterministic policy gate makes the decision that counts: fast accept, escalate to a stronger reasoner, require a human, or block. Where policy disagrees with the fast tag, policy wins.

  5. 05 — Proportion

    Deeper reasoning only where it is needed

    Only escalated requests reach the strong reasoner. Requests that need a person wait for one, and blocked requests stop. Nothing proceeds on the fast tag alone.

  6. 06 — Record

    Bounded action, on the record

    Approved work can act only through a defined, bounded set of tools. Every outcome, including held and blocked requests, is appended to an audit record.

02 Concept

Problem

Many requests an agent handles do not need the most capable, most expensive model. Some do, and some should not be automated at all. Sending everything to one model either wastes reasoning or skips oversight. Laya Runtime is designed to route each request to the level of reasoning and supervision it needs.

Routing only helps if it can be trusted. A fast model that labels a request as simple must not thereby gain permission to act on it, and savings in cost or latency must not quietly come out of quality or oversight.

Laya Runtime is a research runtime exploring whether bounded tasks can be handled quickly and cheaply while risky or ambiguous ones are escalated, high-risk actions stay behind a human, and quality and cost are measured rather than assumed.

Architecture

A dual-process agent runtime, designed so that a fast local layer proposes, a mandatory supervisor checks, and a deterministic policy gate decides the route. A stronger reasoner is called only when the gate escalates; actions run through bounded tools, and every outcome is recorded.

  1. 01Laya — typed fast-path layerGives every request a quick, local first classification in a typed form. The result is provisional.
  2. 02Luna — mandatory supervisorEvery request passes through supervision; nothing routes around it.
  3. 03Deterministic policy gateRules, not a model's judgment, make the routing decision that counts: fast accept, escalate, human required or block.
  4. 04Strong-reasoner interfaceA provider-neutral interface to a more capable model, used only for escalated requests.
  5. 05Bounded tool executionActions run only through a defined, bounded set of tools.
  6. 06Append-only audit and stateDecisions and outcomes are added to a durable record, never overwritten.
  7. 07Fail-closed behaviourWhen a check cannot be completed, the request does not go ahead on the fast path.

Design principles

  • Reason in proportion

    Use deeper reasoning only where the request calls for it.

  • Supervision is not optional

    No request bypasses the supervisor.

  • Policy is deterministic

    What is allowed is decided by rules. A fast model never grants itself authority.

  • Provider-neutral

    The strong reasoner sits behind a stable interface, so the architecture does not depend on any single model provider.

  • Fail closed

    If something cannot be checked, the safe default is to stop or escalate, not to proceed.
